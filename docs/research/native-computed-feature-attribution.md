# Research: native computed Text-Fabric features dominate ORAEC audit (#80)

Measured actual full immutable corpus in [writer run 38173622962](https://github.com/alexsosn/ORAEC-TF/actions/runs/38173622962), artifact 11714614969, final PR #79 head `cf91f302`: **218.193353 seconds** in native `_precompute()`, **0.005152 seconds** in native `_makeApi()`, **238.342612 seconds** in initial warp load, **248.186345 seconds** in inclusive `Fabric.loadAll()`, **300.137853 seconds** complete source-to-graph audit. All **65 semantic TF feature SHA256** unchanged; corpus 13,026 texts / 101,796 sentences / 815,026 real tokens / 3 anchors / 2,930 CR; process peak 5,043,288 KiB. No speedup is claimed.

Upstream Text-Fabric v13.1.0 `tf/core/fabric.py` defines `PRECOMPUTE` in explicit sequence: `__levels__`, `__order__`, `__rank__`, `__levUp__`, `__levDown__`, `__characters__`, `__boundary__`, `__sections__`, `__structure__`. `FabricCore._precompute()` loops `self.precomputeList` and invokes `self.features[fName].load(silent=isSilent())`, skipping inapplicable section/structure features. `Data.load` may read a source-dependent binary pickle cache; the existing separate `tf-build` validation intentionally reloads every real `.tf` file without trusting binary caches. Neither the native feature set nor source trust boundary may be weakened.

Unknown: how much of 218 seconds is spent in each native computed feature, and which computed Python data structure causes high RSS. Next safe experiment is opt-in instrumentation around each of the genuine `Data.load` calls from the existing native precompute method, leaving it and all file validation intact. Export ONLY allowlisted internal TF computed names in timing JSON, never corpus text/path/feature data. Preserve inherited bound-method lookup after success/error. Controlled before/after optimization must await actual results; measurement itself changes no semantics.
