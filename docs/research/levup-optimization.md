# Research: native Text-Fabric levUp is the ORAEC full-corpus hot path (#82)

Actual complete 13,026-text audit run [38175335435](https://github.com/alexsosn/ORAEC-TF/actions/runs/38175335435), artifact 11715992890: Text-Fabric 13.1.0 `__levUp__` native `Data.load` **185.208s** wall, `__order__` **25.253s**, `_precompute` **218.619s**, entire `Fabric.loadAll` **248.800s**, peak RSS **5,043,192 KiB**. All 65 canonical TF feature hashes identical to preprofile corpus, 815,026 tokens, 2,930 CR occurrences. This is a single **baseline observation**; it does not estimate an alternative speedup.

Pinned TF upstream [tf/core/prepare.py](https://github.com/annotation/text-fabric/blob/v13.1.0/tf/core/prepare.py) lines 241–328 computes embedders: (1) build slot→all non-slot containing nodes `oslotsInv`; (2) for *slot* nodes, sort the members of that index by descending `rank`; (3) for each *non-slot* node n with slots L, intersect `oslotsInv[s]` for **every** s in L, remove n itself and sort descending `rank`; (4) intern repeated tuples. The Python `functools.reduce(lambda x,y: x & oslotsInv[y], ...)` repeats allocations across potentially long text oslots. `levDown` is derived from `levUp` and requires exact ordering/embedding semantics.

Candidate **research prototype**, not a production override: choose candidates from the first slot's inverted index and test whether the candidate's full slot set is a superset of the required node slots using set operations, instead of repeatedly intersecting intermediate sets. For identical native behavior include empty non-slot oslots, discontiguous, overlapping and nested slot memberships, slots with no embedders, different TF ranks, technical anchor nodes and zero-length nodes. A set-based proof must retain exact native results, not only approximate counts. Memoization of candidate slot sets trades memory for CPU and must be benchmarked, with capped or explained peak RSS on representative data. Never silently patch `tf.core.prepare.levUp` in the independent audit.

A source-grounded prototype can reveal feasibility, but production optimization belongs in a reproducible, reviewed native TF change or in a source-verified computed-cache artifact with explicit integrity guarantees, NOT a hidden runtime monkeypatch. The mandatory `tf-build` all-source uncached validator and separate independent raw-source-to-Fabric audit remain unchanged.
